IMS Data Channel · 5G New Calling · An LF Networking project

A shared runtime for calls that do more than carry voice.

OpenDCKit is an open, vendor-neutral SDK for the IMS data channel. It gives interactive calling applications one standard runtime, so an app built once behaves the same on any handset, on any network.

/ The problem

Every operator and handset maker is writing the same runtime.

5G New Calling adds a data channel alongside the audio and video of an IMS call, so the two parties on the line can do more together without hanging up. That needs a runtime on the device. Today each vendor builds its own, and an application written for one rarely runs on another.

/ What the project builds

One runtime, built on the standards that already exist.

OpenDCKit implements the existing 3GPP and GSMA specifications rather than inventing new ones, and leaves room for each operator and device maker to add their own features.

/ Runtime

One SDK per device.

Manages the lifecycle of data channel applications in step with call state, so vendors stop shipping parallel implementations. Device UI can be customized through the root application.

/ Standards

Specs first.

Built against GSMA TS.71 for the chipset interfaces and GSMA TS.66 for the JavaScript APIs that applications call, alongside the 3GPP IMS data channel specifications.

/ Extensions

Room to differentiate.

Extended capability interfaces let operators and device makers ship their own features as separate packages, without forking the runtime.

/ Architecture

The middle layer of the device.

The SDK takes call and channel primitives from the device below it and gives the applications above it a stable interface. Applications never talk to the hardware directly.

Reference architecture

From the chipset to the app, during a live call.

A device that integrates OpenDCKit provides the application runtime, with IMS data channel support built into the chipset. During an audio or video call it connects to an IMS network upgraded for data channel, and interactive services appear in the call.

/ Get started

Build in DCLAB before you touch a live network.

DCLAB is an end-to-end simulated data channel environment. Use it to develop and test IMS data channel applications and application servers, and to try the service experience, without standing up an IMS core of your own.

Request a DCLAB account
  1. 01Request a DCLAB account.
  2. 02Build your app against the TS.66 JavaScript APIs.
  3. 03Place a simulated call and load the app into the data channel.
  4. 04Debug the app and its application server end to end.

/ Choose your path

Wherever you sit in the call.

OpenDCKit is useful at every point between the network and the person holding the phone. Pick where you want to contribute.

Operators

Bring requirements from live deployments into the roadmap, and test services against one runtime instead of one per handset.

  • Shape the roadmap through the TSC
  • Interoperability across device makers

Device & chipset makers

Integrate one SDK and keep your own features in extension packages that sit beside it.

  • TS.71 chip interface integration
  • Extension packages, no fork

Application developers

Write an in-call app once against the TS.66 JavaScript APIs and run it on any device that ships OpenDCKit.

  • Start in DCLAB
  • Open issues and code on GitHub
