A shared runtime for calls that do more than carry voice.

OpenDCKit is a proposed open source SDK for the IMS Data Channel: one vendor-neutral runtime that lets an interactive calling application behave the same way on any handset, on any network.

Code on GitHub Join the discussion

What the project builds

5G New Calling adds a data channel alongside the audio and video streams of an IMS call, so the two people on the line can draw, share a file, or work through a visual service menu without leaving the call. Making that work in practice needs a runtime on the device. Today every operator and handset vendor writes their own, and an application built for one rarely runs on another.

One runtime per device

A single SDK that manages the lifecycle of data channel applications, tied to call state, so vendors are not each shipping a parallel implementation.

Standards first

Built against the existing 3GPP and GSMA specifications, including the TS.71 device interfaces and TS.66 JavaScript APIs, rather than defining new ones.

Room for differentiation

Extended capability interfaces let operators and device makers add their own features through separate packages without forking the runtime.

Something to test against

Simulated calls and local application packages let developers build and debug without standing up a live network first.

Where it sits

The SDK is the middle layer. It takes call and channel primitives from the device below it, and exposes a stable interface to the applications above.

Data channel appsWeb applications loaded during a call. They call JavaScript APIs and never talk to the device directly.
OpenDCKitApplication lifecycle, isolated storage, package signing and verification, channel caching, permission gating, and the extended capability plug-in mechanism.
Device and networkCall state and IMS data channel establishment, exposed through the standard device interfaces.

Formation status

OpenDCKit is in formation as a project of LF Networking. It has not launched. This page tracks what is done and what the founding group still needs to agree on.

  1. AgreedProject name and reserved infrastructure: the opendckit GitHub organization and opendckit.org.
  2. AgreedApache License 2.0 for inbound and outbound code, with documentation under CC BY 4.0.
  3. OpenTechnical charter. Draft circulated; the founding group needs to settle the open questions and agree on final language.
  4. OpenInitial maintainers. The charter seats the TSC from the maintainer list, so that list needs to be agreed and landed in a CONTRIBUTING file.
  5. OpenLogo. Concepts are in circulation; the group picks a direction and the final SVG goes to the Linux Foundation.
  6. OpenAsset transfer. Code moves into the opendckit organization, the Linux Foundation is added as an organization owner, and the domain is transferred.
